# Genesis manifest feature

This feature compiles the committed `local-fixture` / `test-only` genesis source and validates and prepares deployment configurations. Production v1 retains four unsigned token-and-reserves operations and its two approval digests. Explicit production v2 adds the six mandatory purpose policies and full Ethereum reserve assembly. There is no wallet or public-network access; every preparation keeps `broadcastAllowed: false`.

V2 binds the complete normalized configuration through `assemblyConfigurationSha256`, alongside the retained deployment/reserve hashes, authenticated artifact identity and ordered operation intents. Nine deployer CREATEs precede founder funding at nonce n+9; the founder GrantVault is CREATE(founder reserve, 1) and consumes no deployer nonce. Eight allocations go directly to their derived reserves. Each purpose vault binds the derived token and Project Controller Safe, with explicit positive opening/window/cap inputs. V1 is never implicitly upgraded.

`constructProductionAssembly` freezes constructors before gas binding; `prepareProductionDeployment` requires all ten selected estimates and checks buffered limits and aggregate fee ceilings. The same private construction kernel serves synthetic local-purpose v2 on chain ID 1, with test-only authority and null approval, without manufacturing accepted production configuration. Local-purpose v1 stays chain 31337. PR2's existing proof runner executes this inventory on an owned synthetic chain and reconstructs its complete gas-bearing package afterward. Native qualification is pending; no observed success is claimed by this provider.

V2 artifact readers require a separately selected clean candidate, authenticate Git objects/vendor inventory and compare with fresh pinned solc output. Exact package reconstruction repeats those checks. There are five artifact kinds, ten offline constructor records, explicit runtime templates and complete materialized immutable expectations. Compiler-input identity binds exact settings and sources. `prepareAssemblyManifest` and the existing passport renderer expose unsigned facts with observed fields null; they invent no child receipt or deployment fact. Hashes bind selected inputs, not a human approval. No explorer verification or release readiness is claimed.

The domain normalizes canonical decimal strings, allocation IDs, recipients and exact sums. The YAML/filesystem/ABI implementations are adapters. `GENESIS_ALLOCATION_HASH` is an integrity commitment to the actual allocations, not evidence that tokenomics were approved.

The package exports `@agent-teams/supply/genesis-manifest`, `@agent-teams/supply/deployment` and `@agent-teams/supply/deployment-files`. The genesis-manifest subpath omits the raw local fixture compiler and its ports; that compilation remains an internal composition flow that strictly parses source text before invoking the typed compiler. Its successful output is content-addressed under the ignored `.local/genesis/` directory and is usable only when its adjacent `READY` marker matches both source and artifact digests. The pure `./deployment` entrypoint exposes validation, unsigned preparation, manifest verification through ports; `./genesis-manifest` (`index.ts`) exports `verifyReserveFacts` and the `agtmai-reserve-public-facts-v1` public-fact contract; `./deployment-files` provides filesystem/artifact adapters and package loaders for operator compositions. Deployment publication uses a separate file-hash inventory; these exports do not confer launch approval. See the [post-custody runbook](../../../../../../docs/architecture/post-custody-operations.md#deployment-configuration-commands) for the distinct commands and envelopes.

Artifact I/O rejects linked source and artifact files, validates runtime manifest bytes before deriving a path, checks the output root after creation, writes with exclusive temporary files, fsyncs, and publishes `READY` last. These checks are fail-closed against accidental or pre-existing link substitution; Node filesystem primitives do not provide a claim of protection against an adversarial same-user process racing path components between syscalls.

`materializeObservedAssemblyManifest` is the synthetic observed variant of the existing full v2 manifest. It checks all ten exact runtimes and immutable getters, founder terms/funding/parent `GrantConfigured`, contract nonces, genesis balances, actual operation inputs and checked receipt costs. The nested vault records the parent transaction and child nonce 1, without an invented child receipt or duplicated gas. The existing passport and facts projection label this selected test-only policy and loopback observation separately from accepted production configuration and unavailable actual production deployment. Offline source inputs do not imply explorer verification. Supply imports neither fixture nor local signer/lifecycle code.

The canonical `test:deployment-plan` gate includes the full same-path proof and its real observation tamper assertions. Public outputs remain under `.local/full-assembly-*/observed/`; the runbook gives native prerequisites and commands. Source reconstruction repeats authenticated artifact admission before scenarios. Pending or uncertain sends are never retried; diagnostics have no READY marker. Bootstrap, gas funding and scenario costs are separate from assembly/genesis, and local fees are not live Ethereum or ETH/USD quotes.
