# Genesis manifest feature

This feature compiles the committed `local-fixture` / `test-only` genesis source and validates and prepares deployment configurations. The legacy deployment compiler serves local/testnet inputs; `validate-production` and `compile-production` use the separate accepted production reserve envelope, two approval digests and required artifact/operation expectations. Production preparation emits unsigned token-and-reserves operations; it neither signs nor broadcasts and does not establish production readiness. Local purpose-reserve preparation is a separate local-only flow, not production six-vault wiring. There is no wallet or public-network access.

The domain normalizes canonical decimal strings, allocation IDs, recipients and exact sums. The YAML/filesystem/ABI implementations are adapters. `GENESIS_ALLOCATION_HASH` is an integrity commitment to the actual allocations, not evidence that tokenomics were approved.

The package exports `@agent-teams/supply/genesis-manifest`, `@agent-teams/supply/deployment` and `@agent-teams/supply/deployment-files`. The genesis-manifest subpath omits the raw local fixture compiler and its ports; that compilation remains an internal composition flow that strictly parses source text before invoking the typed compiler. Its successful output is content-addressed under the ignored `.local/genesis/` directory and is usable only when its adjacent `READY` marker matches both source and artifact digests. The pure `./deployment` entrypoint exposes validation, unsigned preparation, manifest verification and public-fact contracts through ports; `./deployment-files` provides filesystem/artifact adapters and package loaders for operator compositions. Deployment publication uses a separate file-hash inventory; these exports do not confer launch approval. See the [post-custody runbook](../../../../../../docs/architecture/post-custody-operations.md#deployment-configuration-commands) for the distinct commands and envelopes.

Artifact I/O rejects linked source and artifact files, validates runtime manifest bytes before deriving a path, checks the output root after creation, writes with exclusive temporary files, fsyncs, and publishes `READY` last. These checks are fail-closed against accidental or pre-existing link substitution; Node filesystem primitives do not provide a claim of protection against an adversarial same-user process racing path components between syscalls.
